# Data Dictionary — Banking Complaint Resolution Database

Week 2, Exercise 1 deliverable. Describes every table and column created by `database_schema.sql`.
Types, nullability and constraints were read from the database catalog after a clean load, so they match the schema exactly.

- **Database:** PostgreSQL (Supabase). All tables are in the `public` schema with Row Level Security enabled.
- **Sources:** `seeddatacrs.sql` (supplied seed data), the logical ERD (`complaint_erd.png`) and the Exercise 1.3.1 complaint spec.
- **Load order:** `database_schema.sql` → `seeddatacrs.sql` → `seed_validation_queries.sql`.
- **Null? column:** `NO` means the column is required (`NOT NULL`).
- **Source column:** *seeddatacrs.sql* = loaded from the seed file; *Generated by database* = identity key; *Database default* = filled automatically because the seed does not supply it.

## Known limitations

- **Category taxonomy not enforced.** `complaint.category` has no CHECK list because the spec says the taxonomy and severity rules still need business approval. Add a CHECK or lookup table once approved.
- **Spec fields not yet in the seed-driven model.** The spec's data model (§10) also lists subcategory, confidence_score, updated_at on complaint, and an evidence_item table. They were left out so the supplied seed loads unchanged; add them in a later migration with the spec owner's sign-off.
- **Event timestamps.** The seed does not supply times for status changes, recommendations, review requests/decisions or audit rows, so those columns hold the load time.
- **Seed data inconsistencies** (schema accepts them; see `seed_validation.txt` section 5): review_request.status out of step with review_decision for 7 rows; 11 complaints missing their creation history row; RES001 says a fee was reversed while FEE001.reversed is FALSE.
- **Polymorphic audit reference.** `audit_log.entity_id` cannot have a foreign key; validation check 2.20 confirms every reference resolves.
- **CSV vs SQL.** The exercise mentions CSV inputs; the supplied seed was a SQL file and was loaded as SQL.
- **Row Level Security** is enabled with no policies, so the Supabase API returns no rows until access policies are written for the app's roles.
